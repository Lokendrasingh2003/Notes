# 39. Combination Sum

## 📌 Problem

Given an array of **distinct integers** and a `target`, return all unique combinations whose sum equals the target.

The important condition is:

> **The same candidate can be chosen unlimited times.**

### Example

```text
candidates = [2,3,6,7]
target = 7
```

Output:

```text
[[2,2,3], [7]]
```

---

## 🧠 Pattern

**Backtracking / Recursion**

This is a classic **Pick / Not Pick** backtracking problem.

---

## 💡 Key Idea

At every candidate, we have two choices:

```text
1. Pick the current candidate
2. Skip the current candidate
```

The important difference is:

### Pick

```js
backtrack(index, current, remaining - candidates[index])
```

We **stay at the same `index`** because the same number can be used again.

### Skip

```js
backtrack(index + 1, current, remaining)
```

We move to the next candidate because we don't want to use the current candidate anymore.

### Memory Trick

> **Pick → Same index**
> **Skip → Next index**

---

# 🔄 Backtracking Structure

Your function:

```js
function backtrack(index, current, remaining)
```

has three important pieces of information:

| Parameter   | Meaning                                     |
| ----------- | ------------------------------------------- |
| `index`     | Which candidate we're currently considering |
| `current`   | Combination we're currently building        |
| `remaining` | How much more we need to reach target       |

---

# 🛑 Base Cases

### 1. Target reached

```js
if(remaining == 0){
    result.push([...current])
    return
}
```

When:

```text
remaining = 0
```

we found a valid combination.

We use:

```js
[...current]
```

because `current` will later be modified by `pop()`.

---

### 2. No candidates left

```js
if(index === candidates.length){
    return
}
```

We've considered every candidate but haven't reached the target.

---

### 3. Sum exceeded target

```js
if(remaining < 0){
    return
}
```

Since all candidates are positive, once `remaining` becomes negative, this path can never become valid.

---

# 🧩 Pick Case

Your code:

```js
current.push(candidates[index])

backtrack(
    index,
    current,
    remaining - candidates[index]
)
```

Suppose:

```text
candidates = [2,3,6,7]
target = 7
```

We initially choose `2`:

```text
current = [2]
remaining = 5
```

Because `2` can be used again, we call:

```text
backtrack(index = 0)
```

again.

We can choose another `2`:

```text
current = [2,2]
remaining = 3
```

Again:

```text
index = 0
```

We can choose `2` again, or eventually skip it and move to `3`.

---

# ↩️ Backtracking / Undo

After exploring the **pick** path:

```js
current.pop()
```

This is extremely important.

For example:

```text
current = [2,2,3]
```

After finishing that branch:

```text
current.pop()
```

becomes:

```text
[2,2]
```

We then try another possibility.

### Memory Trick

> **Choose → Explore → Undo**

The `pop()` is the **undo step**.

---

# ⏭️ Skip Case

After removing the current candidate:

```js
current.pop()
```

we do:

```js
backtrack(index + 1, current, remaining)
```

This means:

> "Don't use this candidate anymore. Move to the next one."

For example:

```text
[2,3,6,7]
 ↑
index = 0
```

If we skip `2`:

```text
[2,3,6,7]
    ↑
 index = 1
```

Now we consider `3`.

---

# 🌳 Recursion Tree

For:

```text
candidates = [2,3]
target = 5
```

The decision tree starts like:

```text
                    []
                   /  \
                Pick2  Skip2
                 /       \
               [2]       []
              /   \       \
           Pick2  Skip2   Pick3
            /       \       \
         [2,2]     [2]     [3]
                      \
                      [2,3]
```

The valid combination is:

```text
[2,3]
```

---

# 🧪 Dry Run

Let's use:

```text
candidates = [2,3,6,7]
target = 7
```

### Start

```text
current = []
remaining = 7
index = 0
```

### Pick `2`

```text
current = [2]
remaining = 5
index = 0
```

Pick `2` again:

```text
current = [2,2]
remaining = 3
index = 0
```

Pick `2` again:

```text
current = [2,2,2]
remaining = 1
```

Pick `2`:

```text
remaining = -1
```

Stop:

```js
if(remaining < 0) return
```

Backtrack:

```text
[2,2,2,2]
       ↓ pop
[2,2,2]
```

Now skip `2` and move to `3`:

```text
current = [2,2,2]
remaining = 1
index = 1
```

`3` is too large:

```text
remaining = 1 - 3 = -2
```

Stop.

Eventually the recursion reaches:

```text
current = [2,2,3]
remaining = 0
```

So:

```js
result.push([...current])
```

stores:

```text
[2,2,3]
```

The other valid path is:

```text
[7]
```

Final:

```text
[[2,2,3], [7]]
```

# 💻 Your Code

```js
var combinationSum = function(candidates, target) {

    let result = []

    function backtrack(index, current, remaining) {

        // Valid combination found
        if(remaining == 0){
            result.push([...current])
            return
        }

        // No candidates left
        if(index === candidates.length){
            return
        }

        // Target exceeded
        if(remaining < 0){
            return
        }

        // Pick current candidate
        current.push(candidates[index])

        // Same index because we can reuse the candidate
        backtrack(
            index,
            current,
            remaining - candidates[index]
        )

        // Undo the choice
        current.pop()

        // Skip current candidate
        backtrack(
            index + 1,
            current,
            remaining
        )
    }

    backtrack(0, [], target)

    return result
};
```

---

# 🔥 Most Important Part

This is the heart of the problem:

```js
current.push(candidates[index])

backtrack(index, current, remaining - candidates[index])

current.pop()

backtrack(index + 1, current, remaining)
```

Think:

```text
             Current candidate
                    |
             ┌──────┴──────┐
           PICK           SKIP
            |               |
       same index       index + 1
            |
       remaining decreases
```

---

# ❓ Why `index` Instead of `index + 1` After Picking?

This is probably the **most important interview question**.

Suppose:

```text
candidates = [2,3,6,7]
```

We pick `2`.

Because the problem says:

> The same number may be chosen an unlimited number of times.

We must be able to pick `2` again:

```text
[2]
 ↓
[2,2]
 ↓
[2,2,2]
```

Therefore:

```js
backtrack(index, ...)
```

not:

```js
backtrack(index + 1, ...)
```

---

# ❓ Why `index + 1` When Skipping?

If we decide not to use `2`, we don't want to keep considering `2`.

So:

```js
backtrack(index + 1, ...)
```

moves to:

```text
3 → 6 → 7
```

This also prevents duplicate combinations such as:

```text
[2,3]
[3,2]
```

We generate only one ordering:

```text
[2,3]
```

---

# ⚠️ Common Mistakes

### 1. Using `index + 1` after picking

Wrong:

```js
backtrack(index + 1, current, remaining - candidates[index])
```

That would allow each number to be used only once.

---

### 2. Forgetting `pop()`

Wrong:

```js
current.push(candidates[index])
backtrack(...)
backtrack(...)
```

Without:

```js
current.pop()
```

the previous choice remains in the array while exploring the skip branch.

---

### 3. Forgetting to copy the combination

Wrong:

```js
result.push(current)
```

Correct:

```js
result.push([...current])
```

Because `current` continues changing during backtracking.

---

### 4. Not stopping when `remaining < 0`

Because all candidates are positive:

```js
if(remaining < 0) return
```

can safely prune that branch.

---

# ⏱️ Complexity

Backtracking does not have a simple polynomial complexity because it explores combinations.

A common upper-bound description is approximately:

```text
Time: O(N^(T/M))
```

where:

* `N` = number of candidates
* `T` = target
* `M` = smallest candidate

This reflects the potentially exponential number of combinations explored.

### Space

The recursion depth is at most approximately:

```text
T / M
```

so auxiliary recursion space is:

```text
O(T / M)
```

excluding the space used to store the returned combinations.

---

# 🎯 Interview Explanation

If the interviewer asks **"Explain your approach"**, say:

> "I'll use backtracking with a pick-or-skip decision. At each candidate, I can either pick it or skip it. If I pick it, I keep the same index because a candidate can be used unlimited times. If I skip it, I move to the next index. Whenever the remaining target becomes zero, I store a copy of the current combination. If it becomes negative, I stop that branch because all candidates are positive."

## 🧠 Final Memory Trick

```text
Combination Sum
        ↓
   Backtracking
        ↓
   PICK / SKIP
      ↙     ↘
   PICK     SKIP
     ↓        ↓
 SAME INDEX  NEXT INDEX
```

### The 4 lines to remember

```js
current.push(candidates[index])

backtrack(index, current, remaining - candidates[index])

current.pop()

backtrack(index + 1, current, remaining)
```

> **Pick = same index | Skip = next index | Pop = undo**
