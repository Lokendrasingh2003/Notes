# 216. Combination Sum III

## Link : https://leetcode.com/problems/combination-sum-iii/

## 📌 Problem

Find all combinations of exactly `k` different numbers from `1` to `9` whose sum is exactly `n`.

Example:

```text
k = 3
n = 7
```

Possible combinations:

```text
[1,2,4] → 7
```

So:

```text
Output: [[1,2,4]]
```

---

## 🧠 Pattern

**Backtracking + Fixed Range + Pick Once**

The important constraints give us a very small search space:

```text
Numbers available = 1 to 9
Each number = used at most once
Exactly k numbers must be selected
```

So we can simply try every possible combination using backtracking.

---

## 💡 Key Idea

We maintain three things:

```text
start  → where to start choosing numbers
current → numbers selected so far
sum     → sum of selected numbers
```

At every step:

```text
Choose a number
↓
Recurse with i + 1
↓
Remove the number
```

The important part is:

```js
backtrack(i + 1, current, sum + i)
```

Using `i + 1` means the same number cannot be selected again.

---

## 🔍 Your Code

```js
var combinationSum3 = function(k, n) {
    let result = []

    function backtrack(start, current, sum) {

        if (current.length === k) {
            if (sum == n) {
                result.push([...current])
            }
            return
        }

        for (let i = start; i <= 9; i++) {
            current.push(i)

            backtrack(i + 1, current, sum + i)

            current.pop()
        }
    }

    backtrack(1, [], 0)

    return result
}
```

Your solution is correct. ✅

---

# 🔄 How the Recursion Works

We start with:

```js
backtrack(1, [], 0)
```

Meaning:

```text
start = 1
current = []
sum = 0
```

The loop tries:

```text
1, 2, 3, 4, ..., 9
```

For example, if we choose `1`:

```text
current = [1]
sum = 1
```

Then:

```js
backtrack(2, [1], 1)
```

Notice that we pass:

```text
i + 1
```

So now we can choose only:

```text
2,3,4,...,9
```

We cannot choose `1` again.

---

# ⭐ Most Important Part: `i + 1`

This line:

```js
backtrack(i + 1, current, sum + i)
```

is what guarantees:

> **Each number can be used at most once.**

Example:

```text
Choose 2
↓
next start = 3
```

So we can choose:

```text
3,4,5,...,9
```

but not `2` again.

This is the same idea you saw in **Combination Sum II**.

# 🧪 Dry Run

Let's take:

```text
k = 3
n = 7
```

Start:

```text
[]
sum = 0
```

Choose `1`:

```text
[1]
sum = 1
```

Choose `2`:

```text
[1,2]

```

Choose `3`:

```text
[1,2,3]
sum = 6
```

Length is now `3`, which equals `k`.

But:

```text
sum = 6
n = 7
```

So this combination is rejected.

Backtrack:

```text
[1,2]
```

Try `4`:

```text
[1,2,4]
sum = 7
```

Now:

```text
current.length === k
sum === n
```

So:

```js
result.push([1,2,4])
```

Then we backtrack and try other possibilities.

Eventually:

```text
result = [[1,2,4]]
```

# 🛑 Base Case

Your base case is:

```js
if (current.length === k) {
    if (sum == n) {
        result.push([...current])
    }
    return
}
```

This means:

> Once we have selected exactly `k` numbers, there is no reason to select more.

Then we check whether their sum is `n`.

There are two possibilities:

```text
length = k
sum = n  → valid combination
```

or:

```text
length = k
sum ≠ n  → invalid combination
```

---

# ❓ Why Do We Need `[...current]`?

You use:

```js
result.push([...current])
```

This creates a **copy** of the current combination.

If you wrote:

```js
result.push(current)
```

then `result` would store references to the same array that is continuously modified by:

```js
current.pop()
```

So the final result would be incorrect.

# 🔥 Connection With Previous Problems

You have now seen several variations of the same backtracking pattern.

### Combination Sum — #39

```js
backtrack(i, ...)
```

because the same candidate can be reused.

### Combination Sum II — #40

```js
backtrack(i + 1, ...)
```

because each element can be used once.

### Combination Sum III — #216

```js
backtrack(i + 1, ...)
```

because each number from `1–9` can be used once.

The difference is that #216 has a **fixed candidate range**:

```text
1 → 9
```

and requires **exactly k numbers**.

# ⏱️ Complexity

There are only 9 possible numbers, so the search space is very small.

We explore combinations of up to `k` numbers from 9 numbers.

A simple upper-bound description is:

```text
O(2^9)
```

which is effectively constant because `9` is fixed.

More specifically, the number of candidate combinations explored is related to:

```text
C(9, k)
```

The recursion depth is at most:

```text
O(k)
```

and since `k <= 9`:

```text
Auxiliary Space: O(k)
```

excluding the output.

# ⚡ Possible Optimization

Your solution is already correct, but we can stop exploring a branch when the sum becomes greater than `n`.

Because all numbers are positive:

```js
if (sum > n) {
    return
}
```

We can also stop when:

```js
current.length > k
```

although your current base case already prevents going deeper once the length reaches `k`.

A slightly optimized version:

```js
var combinationSum3 = function(k, n) {
    let result = []

    function backtrack(start, current, sum) {

        if (current.length === k) {
            if (sum === n) {
                result.push([...current])
            }
            return
        }

        if (sum > n) {
            return
        }

        for (let i = start; i <= 9; i++) {
            current.push(i)

            backtrack(i + 1, current, sum + i)

            current.pop()
        }
    }

    backtrack(1, [], 0)

    return result
}
```

But your original solution is already accepted and logically correct.

# 🗣️ Interview Explanation

> "I use backtracking to generate combinations from numbers 1 through 9. I maintain the starting index, the current combination, and its sum. For every number, I choose it and recursively continue from `i + 1`, which ensures that every number is used at most once. When the current combination contains exactly `k` numbers, I check whether its sum equals `n`. If it does, I add a copy of the combination to the result. After the recursive call, I remove the last number to backtrack."
