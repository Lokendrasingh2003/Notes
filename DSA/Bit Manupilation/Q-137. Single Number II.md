# 137. Single Number II

## 📌 Problem

Every number appears **exactly 3 times**, except one number that appears **exactly once**.

We need to find that single number.

### Example

```text
nums = [2, 2, 3, 2]

Output = 3
```

---

## 🔍 Your Approach

Your code:

```js
var singleNumber = function(nums) {  

    nums.sort((a,b) => a-b)

    for(let i = 0; i < nums.length; i += 3){

        if(nums[i] != nums[i+1]){
            return nums[i]
        }

    }

    return nums[-1]
};
```

### How it works

After sorting:

```text
[2, 2, 2, 3]
```

You check every group of 3:

```text
2 2 2
3
```

For a normal number:

```text
nums[i] === nums[i+1]
```

But when you reach the single number:

```text
nums[i] !== nums[i+1]
```

So you return `nums[i]`.

### Example

```text
nums = [2,2,3,2]

After sorting:
[2,2,2,3]

i = 0
nums[0] === nums[1]
→ 2 === 2
→ continue

i = 3
nums[3] !== nums[4]
```

Here `nums[4]` is `undefined`, so:

```text
3 !== undefined
```

Therefore it returns:

```text
3
```

So the idea works.

---

## ❌ Why it is not the required solution

The problem specifically requires:

```text
Time: O(n)
Space: O(1)
```

Your solution uses:

```js
nums.sort((a,b) => a-b)
```

Sorting takes:

```text
O(n log n)
```

So your overall complexity is:

```text
O(n log n)
```

Therefore, it violates the **linear runtime requirement**.

Also, this line:

```js
return nums[-1]
```

is not the last element in JavaScript.

In JavaScript:

```js
nums[-1] // undefined
```

To access the last element, use:

```js
nums[nums.length - 1]
```

However, you don't actually need this `return` for the correct bit-manipulation solution.

---

# ⚡ Optimal Approach — Bit Manipulation

The important observation is:

> Every number appears 3 times except one.

We can look at every **bit position separately**.

Suppose we have:

```text
[2, 2, 3, 2]
```

Binary:

```text
2 = 010
2 = 010
3 = 011
2 = 010
```

Count the number of `1`s at each bit position:

```text
Bit position:
       2 1 0

2      0 1 0
2      0 1 0
3      0 1 1
2      0 1 0
       -------
count  0 4 1
```

For every bit belonging to a number that appears 3 times, its count will be a multiple of 3.

So:

```text
count % 3
```

tells us whether that bit belongs to the unique number.

For the example:

```text
0 % 3 = 0
4 % 3 = 1
1 % 3 = 1
```

Therefore:

```text
011 = 3
```

---

## ✅ Code

```js
var singleNumber = function(nums) {

    let result = 0

    for(let i = 0; i < 32; i++){

        let count = 0

        for(let num of nums){

            if(num & (1 << i)){
                count++
            }

        }

        if(count % 3 !== 0){
            result = result | (1 << i)
        }
    }

    return result
};
```

---

# 🧠 How the Code Works

### Step 1: Check each bit

```js
for(let i = 0; i < 32; i++)
```

An integer has 32 bits in JavaScript's bitwise operations.

---

### Step 2: Count set bits

```js
if(num & (1 << i)){
    count++
}
```

`1 << i` creates a number where only the `i`th bit is `1`.

For example:

```text
i = 0 → 0001
i = 1 → 0010
i = 2 → 0100
i = 3 → 1000
```

Then:

```js
num & (1 << i)
```

checks whether that particular bit is set.

---

### Step 3: Use `% 3`

```js
if(count % 3 !== 0)
```

Numbers appearing three times contribute their bits in multiples of 3.

Therefore:

```text
count % 3 === 0
```

means that bit does not belong to the single number.

If:

```text
count % 3 !== 0
```

that bit belongs to the answer.

---

### Step 4: Put that bit into result

```js
result = result | (1 << i)
```

This turns that bit ON in `result`.

---

# ⏱️ Complexity

There are 32 bit positions and `n` numbers.

```text
Time:  O(32 × n)
      = O(n)

Space: O(1)
```

This satisfies the problem's requirements.

---

# 💡 Interview Explanation

You can explain it like this:

> "Since every number appears three times except one, I examine each bit position separately. I count how many numbers have that bit set. For numbers appearing three times, the count will be a multiple of 3. So I take the count modulo 3. If the remainder is non-zero, that bit belongs to the unique number. This gives O(n) time and O(1) extra space."

---

# 🧠 Memory Trick

```text
Every number appears 3 times
            ↓
Check each bit
            ↓
Count 1s
            ↓
count % 3
            ↓
Non-zero → bit belongs to answer
```

### Remember:

**"Count bits → Modulo 3 → Build answer."**

## ⚠️ Important Difference From 136. Single Number

### LeetCode 136

Every number appears **2 times**:

```text
x ^ x = 0
```

So XOR works.

### LeetCode 137

Every number appears **3 times**:

```text
x ^ x ^ x = x
```

So simple XOR does **not** cancel the duplicates.

That's why we use **bit counting + modulo 3**.
