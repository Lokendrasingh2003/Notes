# 148. Sort List

# Link : https://leetcode.com/problems/sort-list/

### Pattern

**Merge Sort + Fast & Slow Pointer + Merge Two Sorted Lists**

### Problem

Given the head of a singly linked list, sort the linked list in **ascending order**.

Example:

```text
Input:
4 → 2 → 1 → 3

Output:
1 → 2 → 3 → 4
```

---

# Key Idea

We use **Merge Sort**.

For an array, Merge Sort is straightforward because we can directly access the middle using indices.

For a linked list, we cannot do that efficiently because we don't have random access.

So we use:

```text
Fast & Slow Pointer
        ↓
Find Middle
        ↓
Split List
        ↓
Recursively Sort Both Halves
        ↓
Merge Two Sorted Lists
```

---

# Step 1: Find the Middle

We use:

```javascript
let slow = head;
let fast = head.next;
```

`slow` moves one step while `fast` moves two steps.

```javascript
while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
}
```

When the loop ends, `slow` points to the **last node of the left half**.

For:

```text
4 → 2 → 1 → 3
```

we get:

```text
4 → 2 | 1 → 3
      ↑
     slow
```

---

# Step 2: Split the List

We save the beginning of the right half:

```javascript
let right = mid.next;
```

Then disconnect the two halves:

```javascript
mid.next = null;
```

Now:

```text
Left:
4 → 2

Right:
1 → 3
```

This is very important.

Without:

```javascript
mid.next = null;
```

the two halves would still be connected.

---

# Step 3: Recursively Sort Both Halves

```javascript
left = sortList(left);
right = sortList(right);
```

For:

```text
4 → 2
```

it becomes:

```text
2 → 4
```

And:

```text
1 → 3
```

becomes:

```text
1 → 3
```

Now we have two sorted lists:

```text
2 → 4

1 → 3
```

---

# Step 4: Merge the Sorted Lists

Now use the standard **Merge Two Sorted Lists** technique.

Compare the first nodes:

```text
2 vs 1
```

`1` is smaller:

```text
1
```

Then compare:

```text
2 vs 3
```

`2` is smaller:

```text
1 → 2
```

Then:

```text
4 vs 3
```

`3` is smaller:

```text
1 → 2 → 3
```

Finally:

```text
4
```

Result:

```text
1 → 2 → 3 → 4
```

---

# Code

```javascript
var sortList = function(head) {

    // Base case
    if (head == null || head.next == null) {
        return head;
    }

    // Find middle
    let mid = findMiddle(head);

    // Split into two halves
    let right = mid.next;
    mid.next = null;

    let left = head;

    // Sort both halves
    left = sortList(left);
    right = sortList(right);

    // Merge sorted halves
    return merge(left, right);
};


function findMiddle(head) {

    if (head == null || head.next == null) {
        return head;
    }

    let slow = head;
    let fast = head.next;

    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
    }

    return slow;
}


function merge(left, right) {

    let dummy = new ListNode(-1);
    let temp = dummy;

    while (left != null && right != null) {

        if (left.val < right.val) {
            temp.next = left;
            temp = left;
            left = left.next;
        }
        else {
            temp.next = right;
            temp = right;
            right = right.next;
        }
    }

    // Attach remaining nodes
    if (left != null) {
        temp.next = left;
    }
    else {
        temp.next = right;
    }

    return dummy.next;
}
```

# Dry Run

Let's take:

```text
4 → 2 → 1 → 3
```

### First Split

```text
4 → 2 | 1 → 3
```

Then recursively:

```text
4 → 2
```

splits into:

```text
4 | 2
```

Both are already single nodes, so they are sorted.

Merge:

```text
4 + 2
```

becomes:

```text
2 → 4
```

Similarly:

```text
1 → 3
```

is already sorted.

Now:

```text
2 → 4

1 → 3
```

Merge them:

```text
1 → 2 → 3 → 4
```

# Why Do We Use `fast = head.next`?

You wrote:

```javascript
let slow = head;
let fast = head.next;
```

This is intentional.

We want `slow` to point to the **last node of the left half**.

For example:

```text
1 → 2 → 3 → 4
```

We want:

```text
1 → 2 | 3 → 4
      ↑
     slow
```

Starting `fast` at:

```javascript
head.next
```

helps us get that split.

This makes:

```javascript
let right = mid.next;
```

safe and gives us two smaller lists.

---

# Why Is `mid.next = null` Important?

This line:

```javascript
mid.next = null;
```

actually **cuts the linked list into two separate lists**.

Before:

```text
4 → 2 → 1 → 3
```

After:

```text
4 → 2

1 → 3
```

If you forget this line, recursion will not properly separate the list and can lead to incorrect behavior or infinite recursion.

---

# Why Does Merge Sort Work Well for Linked Lists?

Merge Sort is especially useful for linked lists because:

### Finding the middle

Using slow/fast pointers:

```text
O(n)
```

### Splitting

We simply change:

```javascript
mid.next = null;
```

No shifting is required.

### Merging

We can merge two lists by changing their `next` pointers.

We don't need to create new nodes for every element.

---

# Complexity

### Time: `O(n log n)`

At every level, we process all `n` nodes during merging.

There are approximately:

```text
log n
```

levels of recursion.

Therefore:

```text
O(n log n)
```

---

### Space: `O(log n)` for your implementation

Your `merge()` uses `O(1)` extra space, but your recursive `sortList()` creates a recursion stack.

The recursion depth is:

```text
O(log n)
```

Therefore your implementation uses:

```text
O(log n)
```

auxiliary stack space.

### Interview Follow-up

The problem asks whether we can achieve:

```text
O(n log n) time
O(1) memory
```

Yes, but that requires an **iterative bottom-up Merge Sort** implementation.

For most interviews, your recursive solution is the standard and much easier version to explain.

# Pattern to Remember

### Merge Sort Pattern

```text
        4 → 2 → 1 → 3
              ↓
          Find Middle
              ↓
        4 → 2 | 1 → 3
          ↓       ↓
       Sort      Sort
          ↓       ↓
        2 → 4   1 → 3
          \       /
           \     /
            Merge
              ↓
        1 → 2 → 3 → 4
```

### One-Line Memory Trick

> **Split → Sort → Merge**

And for a linked list:

> **Slow/Fast to split → Recursion to sort → Two-pointer merge.**

# Common Mistakes

### ❌ Mistake 1: Forgetting to split

```javascript
mid.next = null;
```

is necessary.

---

### ❌ Mistake 2: Using `fast = head`

If your `findMiddle()` is written with:

```javascript
fast = head.next;
```

don't change it to `head` without adjusting the logic.

The purpose is to make `slow` stop at the **end of the left half**.

---

### ❌ Mistake 3: Forgetting the base case

```javascript
if (head == null || head.next == null) {
    return head;
}
```

A single-node list is already sorted.

More importantly, this condition stops the recursion.

---

### ❌ Mistake 4: Creating an array

You could technically copy all values into an array and sort it, but that doesn't satisfy the intended linked-list approach and uses extra space.
