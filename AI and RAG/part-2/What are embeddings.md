# Embeddings

### Simple Definition

**Embeddings** are numerical representations of data such as text, images, or audio that capture their **meaning and relationships**.

For AI and RAG applications, embeddings are mainly used to represent text as vectors so that we can perform **semantic similarity search**.

In simple words:

> **Embeddings convert text into numbers (vectors) in a way that similar meanings produce similar vectors.**

---

### Why Are Embeddings Needed?

Computers cannot directly compare the meaning of sentences like humans do.

For example:

    "I love programming."

and

    "I enjoy coding."

The words are different, but their meanings are similar.

Embeddings represent both sentences as vectors that are relatively close to each other.

    "I love programming."
            ↓
    [0.21, -0.45, 0.78, ...]

    "I enjoy coding."
            ↓
    [0.19, -0.42, 0.75, ...]

The actual values are generated by the embedding model.

---

### How Do Embeddings Work?

The basic process is:

    Text
      ↓
    Embedding Model
      ↓
    Vector
      ↓
    Store / Compare / Search

For example:

    "What is React?"

         ↓

    Embedding Model

         ↓

    [0.12, -0.34, 0.87, 0.45, ...]

The resulting vector represents the semantic information of the input.

---

### What Is a Vector?

A **vector** is simply a list of numbers.

Example:

    [0.12, -0.34, 0.87, 0.45]

Real embedding vectors usually contain many more dimensions.

For example:

    Text
      ↓
    Embedding Model
      ↓
    [0.12, -0.34, 0.87, ...]
    
The number of dimensions depends on the specific embedding model.

---

### Semantic Similarity

**Semantic similarity** means measuring how similar two pieces of text are based on their meaning rather than just matching the exact words.

For example:

    Query:
    "How can I create a React component?"

    Document:
    "React components can be created using functions."

These two texts use different words but have a related meaning.

Their embeddings can therefore be relatively close in vector space.

---

### Cosine Similarity

**Cosine similarity** is a common method for measuring the similarity between two vectors.

Conceptually:

    Vector A
       ↘
        Angle
       ↗
    Vector B

If the vectors point in a similar direction:

    High similarity

If they point in very different directions:

    Low similarity

The cosine similarity value is commonly represented between:

    -1 → Completely opposite direction
     0 → No directional similarity
    +1 → Very similar direction

In many text embedding applications, higher cosine similarity means the texts are more semantically similar.

---

### Embeddings in RAG

Embeddings are a fundamental part of a **RAG system**.

The basic flow is:

    Documents
         ↓
    Split into Chunks
         ↓
    Generate Embeddings
         ↓
    Store Vectors in Vector Database

Then when the user asks a question:

    User Question
         ↓
    Generate Query Embedding
         ↓
    Search Vector Database
         ↓
    Find Similar Document Vectors
         ↓
    Retrieve Relevant Chunks
         ↓
    Send Context to LLM
         ↓
    Generate Answer

---

### Example of Embeddings in RAG

Suppose your company has a document:

    "Employees receive 20 days of paid leave every year."

The document chunk is converted into an embedding:

    Document Chunk
         ↓
    Embedding Model
         ↓
    Document Vector
         ↓
    Vector Database

Now the user asks:

    "How many paid leaves do employees get?"

The question is also converted into an embedding:

    User Question
         ↓
    Embedding Model
         ↓
    Query Vector

The vector database compares the query vector with stored document vectors and retrieves the relevant document.

    Query Vector
         ↓
    Similarity Search
         ↓
    Relevant Document
         ↓
    LLM
         ↓
    Answer

---

### Embedding Model vs LLM

An **embedding model** and an **LLM** serve different purposes.

#### Embedding Model

Main purpose:

> Convert information into vectors for tasks such as semantic search and similarity comparison.

    Text
      ↓
    Embedding Model
      ↓
    Vector

#### LLM

Main purpose:

> Understand context and generate text.

    Prompt
      ↓
    LLM
      ↓
    Generated Response

In a RAG application, both can work together:

    User Question
         ↓
    Embedding Model
         ↓
    Query Vector
         ↓
    Vector Database
         ↓
    Relevant Context
         ↓
    LLM
         ↓
    Answer

---

### Embeddings vs Token Embeddings

This is an important interview distinction.

**Token embeddings** are internal representations used by an LLM as part of processing tokens.

**Text embeddings** are usually generated by dedicated embedding models for tasks such as:

- Semantic search
- Similarity search
- Retrieval
- Clustering
- Recommendations

So:

> **Token embeddings help an LLM process tokens, while text embeddings are commonly used to represent text for semantic search and retrieval.**

---

### Where Are Embeddings Stored?

Embeddings are commonly stored in a **vector database**.

Examples:

- Pinecone
- FAISS
- Chroma
- Weaviate
- Milvus

The vector database allows applications to efficiently search for vectors that are similar to a query vector.

---

### Important Point

Embeddings do not store text as a simple human-readable summary.

Instead, they represent information as a high-dimensional numerical vector that captures patterns and semantic relationships learned by the embedding model.

---

### Interview Answer

If the interviewer asks:

**"What are embeddings?"**

You can answer:

> **"Embeddings are numerical vector representations of data that capture semantic meaning and relationships. In RAG systems, we convert documents and user queries into embeddings and store the document embeddings in a vector database. When a user asks a question, we generate an embedding for the query and perform similarity search to retrieve the most relevant document chunks, which are then provided to the LLM as context."**
