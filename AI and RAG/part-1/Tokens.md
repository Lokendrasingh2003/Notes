# Tokens

### Simple Definition

A **token** is a small unit of text that an LLM processes.

A token can be:

- A complete word
- Part of a word
- A punctuation mark
- A space or piece of text

For example:

    "Hello, how are you?"

May be split into tokens such as:

    ["Hello", ",", " how", " are", " you", "?"]

The exact tokens depend on the **tokenizer** used by the model.

---

### Why Do LLMs Use Tokens?

LLMs cannot directly process normal human-readable text.

The text must first be converted into tokens and then into numerical representations that the neural network can process.

    Text
      ↓
    Tokenization
      ↓
    Tokens
      ↓
    Token IDs
      ↓
    Numerical Representations
      ↓
    Transformer

---

### What Is Tokenization?

**Tokenization** is the process of breaking text into smaller units called **tokens**.

For example:

    "I love programming"

    ↓

    ["I", " love", " programming"]

Each token is then mapped to a numerical **Token ID**.

Conceptually:

    "I"           → 40
    " love"       → 1256
    " programming" → 8372

The actual token IDs depend on the tokenizer and vocabulary of the model.

---

### Word vs Token

A token is **not always equal to one word**.

For example, a word may be divided into multiple tokens:

    "unbelievable"

    ↓

    ["un", "believ", "able"]

Similarly, common words may sometimes be represented as a single token.

Therefore:

> **1 word ≠ always 1 token**

---

### Tokens and Numbers

The LLM ultimately works with numbers.

The general process is:

    Text
      ↓
    Tokens
      ↓
    Token IDs
      ↓
    Embeddings
      ↓
    Transformer

For example:

    "React is powerful"

         ↓

    ["React", " is", " powerful"]

         ↓

    [1254, 318, 9274]

         ↓

    Embeddings

         ↓

    Transformer

---

### Input Tokens and Output Tokens

LLMs process both **input tokens** and **output tokens**.

#### Input Tokens

Tokens that come from the user's prompt.

Example:

    User:
    "What is React?"

These words are converted into input tokens.

#### Output Tokens

Tokens generated by the LLM in its response.

For example:

    "React is a JavaScript library."

The model generates the response **one token at a time**.

---

### Token Prediction

LLMs generate text by predicting the next token.

For example:

    Input:
    "React is a JavaScript"

         ↓

    Predict next token

         ↓

    "library"

Then:

    "React is a JavaScript library"

         ↓

    Predict next token

         ↓

    "used"

This process continues until the model finishes the response.

    Prompt
      ↓
    Predict Token 1
      ↓
    Predict Token 2
      ↓
    Predict Token 3
      ↓
    ...
      ↓
    Final Response

---

### Tokens and Context Window

A **context window** is the maximum amount of tokens an LLM can process as context at one time.

For example, if a model supports a context window of **100,000 tokens**, the input and relevant context must fit within that limit.

The context window can include:

- User prompts
- Previous conversation
- System instructions
- Retrieved RAG documents
- Generated content

Conceptually:

    System Instructions
           +
    Conversation
           +
    User Prompt
           +
    RAG Context
           ↓
    Context Window

---

### Tokens and Cost

For many LLM APIs, usage is measured using **tokens**.

Cost can depend on:

- Input tokens
- Output tokens
- The model being used

For example:

    Input Tokens
         +
    Output Tokens
         ↓
    Total Token Usage

Therefore, reducing unnecessary input and output tokens can help reduce **API cost and latency**.

---

### Tokens in RAG

Tokens are also important in RAG systems.

A document may be:

    Large Document
         ↓
    Text Extraction
         ↓
    Chunking
         ↓
    Token / Text Limits
         ↓
    Embedding
         ↓
    Vector Database

When retrieving documents for an LLM, the retrieved context must fit within the model's context window.

---

### Important Interview Point

> **"Tokens are the basic units of text processed by an LLM. Text is first tokenized, then tokens are converted into token IDs and numerical representations. The Transformer processes these representations, and the model generates output by predicting the next token repeatedly."**

### Key Takeaways

- **Token = basic unit of text processed by an LLM**
- A token can be a word, part of a word, punctuation, or another piece of text.
- **Tokenization = converting text into tokens**
- Tokens are mapped to **Token IDs**.
- Token IDs are converted into numerical representations such as **embeddings**.
- LLMs generate responses by predicting **one token at a time**.
- Context windows are measured in **tokens**.
- LLM API usage and cost are often measured in **tokens**.
- **1 word is not necessarily equal to 1 token.**
