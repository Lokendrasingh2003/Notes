# 56. Merge Intervals

## 📌 Pattern

**Sorting + Greedy**

---

## 📌 Problem

We are given intervals like:

```text
[1,3]
[2,6]
[8,10]
[15,18]
```

We need to merge intervals that **overlap**.

Expected:

```text
[1,6]
[8,10]
[15,18]
```

---

# ⚡ Key Idea

First, **sort intervals by their starting point**.

```js
intervals.sort((a,b) => a[0] - b[0])
```

After sorting, we process intervals from left to right.

For every interval, compare it with the **last interval in `result`**.

There are only two cases:

### Case 1: No overlap

```text
Current start > Previous end
```

Then they are separate intervals.

```text
[1,3]   [8,10]
       ↑
       8 > 3
```

So add the current interval to `result`.

---

### Case 2: Overlap

```text
Current start <= Previous end
```

Then merge them.

```text
[1,3]
   [2,6]
```

They overlap because:

```text
2 <= 3
```

Merged interval:

```text
[1,6]
```

The end should be the larger of both ends:

```js
Math.max(currentEnd, previousEnd)
```

---

# 🧠 Your Code

```js
var merge = function(intervals) {
    intervals.sort((a,b) => a[0] - b[0])

    let result = []

    for(let i = 0; i < intervals.length; i++){

        if(
            result.length == 0 ||
            intervals[i][0] > result[result.length - 1][1]
        ){
            result.push(intervals[i])
        }
        else {
            result[result.length - 1][1] =
                Math.max(
                    intervals[i][1],
                    result[result.length - 1][1]
                )
        }
    }

    return result
};
```

Your code is correct.

---

# 🔍 Step 1: Sort the Intervals

```js
intervals.sort((a,b) => a[0] - b[0])
```

We sort using the **start value**.

For example:

```text
Input:

[4,7]
[1,4]
[2,5]
[8,10]
```

After sorting:

```text
[1,4]
[2,5]
[4,7]
[8,10]
```

Why do we need sorting?

Because now we know that intervals are processed from **left to right**.

That makes it easy to determine whether the current interval overlaps the previous merged interval.

---

# 🔍 Step 2: Create Result

```js
let result = []
```

Initially:

```text
result = []
```

We will store our merged intervals here.

---

# 🔍 Step 3: Check the First Interval

```js
if(
    result.length == 0 ||
    intervals[i][0] > result[result.length - 1][1]
)
```

The first condition:

```js
result.length == 0
```

means:

> There is nothing in `result` yet.

So simply add the first interval:

```js
result.push(intervals[i])
```

---

# 🔍 Step 4: Check for Overlap

Suppose:

```text
result = [[1,3]]
current = [2,6]
```

We check:

```js
intervals[i][0] > result[result.length - 1][1]
```

Substitute values:

```text
2 > 3
```

False.

Therefore, they overlap.

So we go into `else`.

---

# 🔍 Step 5: Merge

```js
result[result.length - 1][1] =
    Math.max(
        intervals[i][1],
        result[result.length - 1][1]
    )
```

We have:

```text
result = [[1,3]]
current = [2,6]
```

Compare the ends:

```text
current end  = 6
result end   = 3
```

Take the larger one:

```text
max(6,3) = 6
```

So:

```text
result = [[1,6]]
```

# 🔑 The Most Important Condition

Remember this:

```js
if(currentStart > previousEnd)
```

### If true:

```text
No overlap
```

Add a new interval.

### If false:

```text
Overlap
```

Merge intervals.

In simple form:

```text
currentStart > previousEnd
        ↓
   No overlap

currentStart <= previousEnd
        ↓
      Merge
```

# 🤔 Why Compare With `result[result.length - 1]`?

This is an important interview question.

Suppose:

```text
[1,3]
[2,6]
[4,8]
```

After the first two intervals:

```text
result = [[1,6]]
```

Now current interval is:

```text
[4,8]
```

We should compare it with:

```text
[1,6]
```

not with the original `[2,6]`.

That's why we use:

```js
result[result.length - 1]
```

It represents the **latest merged interval**.

Then:

```text
[1,6]
[4,8]
```

overlap and become:

```text
[1,8]
```

---

# 📌 Why `Math.max()`?

Consider:

```text
[1,10]
[2,5]
```

They overlap.

If we simply used the current end:

```text
5
```

we would incorrectly make:

```text
[1,5]
```

But `[1,10]` already extends to `10`.

So we need:

```js
Math.max(10,5)
```

which gives:

```text
10
```

Therefore:

```text
[1,10]
```

remains correct.

# ⚠️ Common Mistakes

### 1. Forgetting to sort

Without:

```js
intervals.sort((a,b) => a[0] - b[0])
```

the greedy approach doesn't work reliably.

---

### 2. Checking the wrong condition

Correct:

```js
currentStart > previousEnd
```

means **no overlap**.

If:

```text
currentStart <= previousEnd
```

they overlap.

---

### 3. Using current end directly

Don't do:

```js
result[last][1] = intervals[i][1]
```

Instead:

```js
result[last][1] =
    Math.max(result[last][1], intervals[i][1])
```

because the previous merged interval might extend farther.

---

### 4. Comparing only with the original previous interval

Always compare with:

```js
result[result.length - 1]
```

because it may already contain multiple merged intervals.

---

# ⏱️ Complexity

### Sorting

```js
intervals.sort(...)
```

takes:

```text
O(n log n)
```

### Traversing

We visit every interval once:

```text
O(n)
```

Therefore:

**Time:**

```text
O(n log n)
```

**Space:**

```text
O(n)
```

for the `result` array.

The sorting implementation may also use additional internal space depending on the JavaScript engine.

# 🎯 Interview Explanation

If the interviewer asks **"Explain your approach"**, say:

> "First, I sort the intervals by their starting point. Then I iterate through them and compare each interval with the last interval in the result. If the current start is greater than the previous end, there is no overlap, so I add a new interval. Otherwise, the intervals overlap, so I merge them by keeping the same start and taking the maximum of the two end values."

# 🧠 Memory Trick

Remember:

```text
SORT → COMPARE → MERGE
```

More specifically:

```text
Sort by start
      ↓
current start > previous end?
      ↓
   YES → New interval
   NO  → Merge
```

And when merging:

```text
New End = Math.max(oldEnd, currentEnd)
```

### One-line memory trick:

> **Sort first, then compare current start with the last merged end.**
