# 40. Combination Sum II

## 📌 Problem

Given an array `candidates` that may contain duplicates, find all **unique combinations** whose sum equals `target`.

Two important rules:

1. Each element can be used **only once**.
2. The result must not contain duplicate combinations.

### Example

```text
candidates = [10,1,2,7,6,1,5]
target = 8
```

After sorting:

```text
[1,1,2,5,6,7,10]
```

Valid combinations:

```text
[1,1,6]
[1,2,5]
[1,7]
[2,6]
```

---

# 🧠 Pattern

**Backtracking + Sorting + Duplicate Skipping**

---

# 💡 Key Idea

There are **three important differences** from Combination Sum (39).

### Combination Sum 39

A number can be reused:

```js
backtracking(i, ...)
```

### Combination Sum II

A number can only be used once:

```js
backtracking(i + 1, ...)
```

### Duplicate handling

Because the input can contain duplicates, we skip duplicates at the **same recursion level**:

```js
if(i > index && candidates[i] === candidates[i - 1]){
    continue
}
```

### Memory Trick

> **Sort → Loop → Skip Duplicate → Pick → Move Next**

---

# 1️⃣ Sort the Array

Your first step:

```js
candidates.sort((a,b) => a-b)
```

Example:

```text
Before:
[10,1,2,7,6,1,5]

After:
[1,1,2,5,6,7,10]
```

Sorting is important for **two reasons**:

### Reason 1 — Duplicate detection

After sorting, duplicates are next to each other:

```text
[1,1,2,5,6,7,10]
 ↑ ↑
 duplicate
```

So we can detect them with:

```js
candidates[i] === candidates[i-1]
```

### Reason 2 — Early stopping

Because the array is sorted:

```js
if(candidates[i] > remaining){
    break
}
```

If the current number is already too large, every number after it will also be too large.

---

# 2️⃣ Use a Loop for Choices

Your recursion uses:

```js
for(let i = index; i < candidates.length; i++)
```

This means:

> "From the current position onward, try every possible candidate."

For example:

```text
[1,1,2,5,6,7]
 ↑
index = 0
```

Possible choices are:

```text
1
1
2
5
6
7
```

---

# 3️⃣ Skip Duplicate Choices

This line is the **most important line** in the problem:

```js
if(i > index && candidates[i] === candidates[i-1]){
    continue
}
```

Let's understand exactly why `i > index` is necessary.

Suppose:

```text
[1,1,2]
```

At the same recursion level:

```text
       []
      / | \
     1  1  2
```

The first `1` should be considered.

But the second `1` would create the **same combination choices**, so we skip it.

```text
if(i > index && candidates[i] === candidates[i-1])
```

means:

> "If this is not the first choice at this recursion level and it is the same as the previous choice, skip it."

---

# 🔥 Very Important: Same Level vs Different Level

This is where many people get confused.

Consider:

```text
candidates = [1,1,6]
target = 8
```

We **must** allow:

```text
[1,1,6]
```

So we cannot simply skip every duplicate.

We only skip duplicates when they are choices at the **same recursion level**.

### First `1`

```text
index = 0
i = 0
```

Condition:

```text
i > index
0 > 0 → false
```

So we use it.

Then recursion starts from:

```text
backtracking(1,...)
```

At the next level:

```text
index = 1
```

Now the second `1` can be chosen:

```text
i = 1
i > index → false
```

So:

```text
[1,1]
```

is allowed.

### Memory Trick

> **Same level → skip duplicate**
> **Different level → duplicate is allowed**

---

# 4️⃣ Each Element Can Be Used Once

This line:

```js
backtracking(i+1, current, remaining-candidates[i])
```

is what ensures each element is used only once.

Suppose we choose:

```text
index = 2
```

Then the next recursion starts from:

```text
index = 3
```

So we can never choose index `2` again.

Compare this with Combination Sum 39:

```js
backtracking(i, ...)
```

because reuse was allowed there.

### Easy Memory Trick

```text
Combination Sum:
Pick → same index

Combination Sum II:
Pick → next index
```

---

# 5️⃣ Pick and Backtrack

Your core code:

```js
current.push(candidates[i])

backtracking(
    i + 1,
    current,
    remaining - candidates[i]
)

current.pop()
```

This follows the standard backtracking pattern:

```text
Choose
  ↓
Explore
  ↓
Undo
```

### `push()`

Choose the candidate:

```js
current.push(candidates[i])
```

### Recursive call

Explore combinations using the remaining candidates:

```js
backtracking(i+1, ...)
```

### `pop()`

Undo the choice:

```js
current.pop()
```

so the next candidate can be tried.

---

# 6️⃣ Stop When Sum Is Reached

```js
if(remaining == 0){
    result.push([...current])
    return
}
```

When:

```text
remaining = 0
```

we found a valid combination.

We use:

```js
[...current]
```

to store a copy because `current` will continue changing during backtracking.

---

# 7️⃣ Early Break

Your code:

```js
if(candidates[i] > remaining){
    break
}
```

This is possible because the array is sorted.

Example:

```text
candidates = [1,2,5,6,7]
remaining = 4
```

When:

```text
i → 5
```

we know:

```text
5 > 4
```

And because everything after `5` is even larger:

```text
6 > 4
7 > 4
```

there is no point checking them.

So:

```js
break
```

saves unnecessary recursion.

# 🧪 Dry Run

Let's use:

```text
candidates = [1,1,2,5,6,7,10]
target = 8
```

### Start

```text
current = []
remaining = 8
index = 0
```

At this level:

```text
i = 0 → 1
i = 1 → 1
i = 2 → 2
i = 3 → 5
...
```

### Choose first `1`

```text
current = [1]
remaining = 7
```

Recursive call:

```text
index = 1
```

Now the second `1` is available.

Choose it:

```text
current = [1,1]
remaining = 6
```

Then choose `6`:

```text
current = [1,1,6]

```

Store:

```text
[1,1,6]
```

### Backtrack

Remove `6`:

```text

```

Eventually:

```text
[1,2,5]
```

is found.

```text
[1,7]
```

is found.

Finally another branch produces:

```text
[2,6]
```

Final result:

```text
[
  [1,1,6],
  [1,2,5],
  [1,7],
  [2,6]

```

# 🌳 Recursion Decision

The structure is slightly different from Combination Sum 39 because you use a loop.

Think of:

```text
backtracking(index)
        |
        |--- choose candidates[index]
        |
        |--- choose candidates[index + 1]
        |
        |--- choose candidates[index + 2]
        |
        └--- ...
```

For every choice:

```text
Pick
 ↓
Recursive call from i + 1
 ↓
Pop
 ↓
Try next candidate
```

---

# 💻 Your Code

```js
var combinationSum2 = function(candidates, target) {

    let result = []

    // Sort for duplicate handling and early stopping
    candidates.sort((a,b) => a-b)

    function backtracking(index, current, remaining) {

        // Target reached
        if(remaining == 0){
            result.push([...current])
            return
        }

        for(let i = index; i < candidates.length; i++){

            // Skip duplicate choices at the same level
            if(i > index && candidates[i] === candidates[i-1]){
                continue
            }

            // Since array is sorted, no later value can work
            if(candidates[i] > remaining){
                break
            }

            // Choose
            current.push(candidates[i])

            // i + 1 because each element can be used only once
            backtracking(
                i + 1,
                current,
                remaining - candidates[i]
            )

            // Undo
            current.pop()
        }
    }

    backtracking(0, [], target)

    return result
};
```

---

# 🔥 The Three Most Important Lines

### 1. Sort

```js
candidates.sort((a,b) => a-b)
```

Needed for duplicate detection and pruning.

### 2. Skip duplicates at the same level

```js
if(i > index && candidates[i] === candidates[i-1]){
    continue
}
```

Prevents duplicate combinations.

### 3. Move to `i + 1`

```js
backtracking(i + 1, ...)
```

Ensures each element is used only once.

---

# ⚔️ Combination Sum vs Combination Sum II

|                  | Combination Sum | Combination Sum II     |
| ---------------- | --------------- | ---------------------- |
| Input duplicates | No              | Yes                    |
| Reuse element    | ✅ Unlimited     | ❌ Once                 |
| Pick recursion   | `backtrack(i)`  | `backtrack(i+1)`       |
| Sort required    | Not necessary   | ✅ Yes                  |
| Duplicate skip   | Not needed      | ✅ Required             |
| Main technique   | Backtracking    | Backtracking + Sorting |

### Easy Comparison

```text
39:
Pick → same index
Skip → next index

40:
Pick → next index
Duplicate at same level → skip
```

# ⚠️ Common Mistakes

### 1. Using `backtracking(i, ...)`

Wrong:

```js
backtracking(i, current, remaining)
```

That allows the same element to be reused.

Correct:

```js
backtracking(i + 1, current, remaining)
```

---

### 2. Skipping every duplicate

Wrong idea:

```js
if(candidates[i] === candidates[i-1])
    continue
```

This could prevent valid combinations like:

```text
[1,1,6]
```

Correct:

```js
if(i > index && candidates[i] === candidates[i-1])
```

Only skip duplicates at the **same recursion level**.

---

### 3. Forgetting to sort

Without:

```js
candidates.sort((a,b) => a-b)
```

this duplicate check won't reliably work:

```js
candidates[i] === candidates[i-1]
```

and the early `break` would also be invalid.

---

### 4. Forgetting `pop()`

Without:

```js
current.pop()
```

previous choices remain in the current combination and corrupt other branches.

---

# ⏱️ Complexity

Backtracking has exponential worst-case behavior because many combinations may need to be explored.

A common upper bound is approximately:

```text
O(2^n)
```

for exploring subsets/choices, although the actual behavior is strongly affected by the target, candidate values, and pruning.

Sorting costs:

```text
O(n log n)
```

So the overall complexity is dominated by the backtracking search.

### Space

The recursion depth can be at most `O(n)`.

Ignoring the output:

```text
Auxiliary Space = O(n)
```

The returned combinations themselves require additional output space.

# 🎯 Interview Explanation

If the interviewer asks **"Explain your approach"**, say:

> "First, I sort the candidates so duplicate values are adjacent and I can stop early when a value becomes greater than the remaining target. Then I use backtracking. For each position, I choose a candidate and recursively continue from `i + 1`, because each element can only be used once. To avoid duplicate combinations, I skip a candidate when it is equal to the previous candidate at the same recursion level using `i > index`. After exploring a choice, I remove it with `pop()`."

# 🧠 Final Memory Trick

Remember these **4 rules**:

```text
1. SORT
2. SAME LEVEL DUPLICATE → SKIP
3. PICK → i + 1
4. POP → BACKTRACK
```

### Most Important Line

```js
if(i > index && candidates[i] === candidates[i-1]){
    continue
}
```

Think:

> **"If this is not my first choice at this level and it is the same as the previous choice, skip it."**

### One-line pattern

> **Sort → Loop → Skip same-level duplicates → Pick → `i+1` → Pop**
