# 77. Combinations

## 📌 Problem

Given two integers `n` and `k`, return all combinations of `k` numbers chosen from:

```text
[1, n]
```

Example:

```text
n = 4
k = 2
```

The answer is:

```text
[
  [1,2],
  [1,3],
  [1,4],
  [2,3],
  [2,4],
  [3,4]
]
```

Notice:

```text
[1,2] and [2,1]
```

are considered the **same combination**.

So we only need to generate one of them.

---

## 🧠 Pattern

**Backtracking + Combinations**

The pattern is:

```text
Choose → Recurse → Undo
```

We maintain:

```text
index   → where to start choosing
current → current combination
```

---

## 💡 Key Idea

We always choose numbers from left to right:

```text
1 → 2 → 3 → 4
```

After choosing `i`, we call:

```js
backtrack(i + 1, current)
```

This means:

> Don't choose `i` again, and don't go backward.

For example, after choosing `2`, we only consider:

```text
3, 4, ...
```

So:

```text
[1,2]
```

can be generated, but:

```text
[2,1]
```

can never be generated.

This automatically avoids duplicate combinations.

---

# 🔍 Your Code

```js
var combine = function(n, k) {
    let result = []

    function backtrack(index, current) {

        if(current.length == k){
            result.push([...current])
            return
        }

        for(let i = index; i <= n; i++){

            current.push(i)

            backtrack(i + 1, current)

            current.pop()
        }
    }

    backtrack(1, [])

    return result
};
```

Your solution is correct. ✅

---

# 🔄 How It Works

We start with:

```js
backtrack(1, [])
```

This means:

```text
start from 1
current combination = []
```

The loop:

```js
for(let i = index; i <= n; i++)
```

tries every possible number from the current starting point.

For each number:

```js
current.push(i)
```

we choose it.

Then:

```js
backtrack(i + 1, current)
```

we continue choosing numbers after it.

Finally:

```js
current.pop()
```

undoes the choice so we can try another number.

---

# 🌳 Recursion Tree

For:

```text
n = 4
k = 2
```

the recursion starts like:

```text
                         []
             /       /       \       \
            1        2         3       4
          / | \      / \        |
         2  3  4    3   4
```

Complete combinations:

```text
[1,2]
[1,3]
[1,4]

[2,3]
[2,4]

[3,4]
```

Notice there is no:

```text
[2,1]
[3,1]
[3,2]
```

because after choosing a number, we only move forward.

---

# ⭐ Most Important Line

```js
backtrack(i + 1, current)
```

This is what makes it a **combination** problem rather than a permutation problem.

Suppose:

```text
current = [1]
```

and we choose `2`.

We call:

```text
backtrack(3, [1,2])
```

Now only:

```text
3, 4, ...
```

can be selected.

Therefore:

```text
[1,2]
```

is possible.

But:

```text
[2,1]
```

is impossible.

# 🧪 Dry Run

Let's take:

```text
n = 4
k = 2
```

Start:

```text
current = []
index = 1
```

### Choose `1`

```text
current = [1]
```

Then:

```text
backtrack(2, [1])
```

Now choose `2`:

```text
current = [1,2]
```

Length is `2`, which equals `k`.

So:

```js
result.push([1,2])
```

Then:

```text

```

gives:

```text
[1]
```

Now choose `3`:

```text
[1,3]
```

Store it.

Then:

```text
[1,4]
```

Store it.

Backtrack all the way:

```text
[]
```

Now choose `2`:

```text
[2]
```

Since we called:

```text
backtrack(3, [2])
```

we can choose:

```text
3
4
```

giving:

```text
[2,3]
[2,4]
```

Finally:

```text
[3,4]
```

is generated.

# 🛑 Base Case

Your base case is:

```js
if(current.length == k){
    result.push([...current])
    return
}
```

This means:

> Once we have selected exactly `k` numbers, we have a complete combination.

We store it and stop exploring that branch.

---

# ❓ Why `[...current]`?

You use:

```js
result.push([...current])
```

This creates a copy of the current combination.

This is important because:

```js
current.pop()
```

will later modify `current`.

If we did:

```js
result.push(current)
```

the stored results would reference the same array.

So always remember:

```text
current → working array
[...current] → snapshot to store
```

# 🔥 Why This Doesn't Need Duplicate Checking

Compare this with **Subsets II**.

In Subsets II, the input itself could contain duplicates:

```text
[1,2,2]
```

so we needed:

```js
if(i > index && nums[i] === nums[i-1]){
    continue
}
```

Here the numbers are:

```text
1,2,3,...,n
```

and are naturally unique.

Also, because we always move forward:

```js
i + 1
```

we never generate:

```text
[2,1]
```

after:

```text
[1,2]
```

So no duplicate-skip condition is required.

# 🔗 Combination vs Permutation

This is an important interview distinction.

### Combination

Order doesn't matter:

```text
[1,2] = [2,1]
```

So we move forward:

```js
backtrack(i + 1, current)
```

### Permutation

Order matters:

```text
[1,2] ≠ [2,1]
```

So we need a different approach, usually with a `used` array.

### Memory Trick

> **Combination → move forward**
> **Permutation → can choose unused elements from anywhere**

---

# 📊 Number of Combinations

The total number of combinations is:

```text
C(n, k)
```

For:

```text
n = 4
k = 2
```

we have:

```text
C(4,2) = 6
```

So the output contains exactly `C(n,k)` combinations.

---

# ⏱️ Complexity

There are:

```text
C(n,k)
```

valid combinations.

Each combination contains `k` elements, and we copy it using:

```js
[...current]
```

Therefore, a useful output-sensitive complexity is:

```text
Time: O(C(n,k) × k)
```

The recursion depth is at most `k`:

```text
Auxiliary Space: O(k)
```

excluding the output.

Output space:

```text
O(C(n,k) × k)
```

---

# 🗣️ Interview Explanation

> "I use backtracking to generate combinations of size `k`. I start from 1 and try every number up to `n`. When I choose a number `i`, I recursively continue from `i + 1`, which ensures that I don't reuse the same number and that numbers are always selected in increasing order. When the current combination reaches size `k`, I add a copy to the result. After exploring a choice, I remove it using `pop` to backtrack."

Remember:

```text

  ↓

  ↓

```

### Most important line:

```js

```

> **`i + 1` = no reuse + increasing order + no duplicate combinations**

> **Pick → Explore → Pop**
