# 142. Linked List Cycle II

# Link : https://leetcode.com/problems/linked-list-cycle-ii/

### Pattern

**Fast & Slow Pointer (Floyd's Cycle Detection)**

### Problem

Given the head of a linked list, return the **node where the cycle begins**.

If there is no cycle, return `null`.

---

### Key Idea

This problem has **2 phases**:

#### Phase 1: Detect the Cycle

Use two pointers:

* `slow` → moves 1 step
* `fast` → moves 2 steps

If they meet, a cycle exists.

#### Phase 2: Find the Cycle Entry

Once `slow` and `fast` meet:

* Create another pointer `entry = head`.
* Move `entry` and `slow` **one step at a time**.
* The point where they meet is the **starting node of the cycle**.

---

### Code

```javascript
var detectCycle = function(head) {
    let slow = head;
    let fast = head;

    // Phase 1: Detect cycle
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;

        if (slow == fast) {

            // Phase 2: Find cycle entry
            let entry = head;

            while (entry !== slow) {
                entry = entry.next;
                slow = slow.next;
            }

            return entry;
        }
    }

    return null;
};
```

---

### Example

```text
1 → 2 → 3 → 4 → 5
        ↑       ↓
        ← ← ← ←
```

The cycle starts at node `3`.

First, `slow` and `fast` meet somewhere inside the cycle:

```text
slow == fast
```

Then:

```text
entry = head
slow  = meeting point
```

Move both one step:

```text
entry → 2 → 3
slow  → 4 → 3
```

They meet at:

```text
3
```

Therefore, `3` is the cycle entry.

---

### Why does the second phase work?

Suppose:

```text
a = distance from head to cycle entry
b = distance from cycle entry to meeting point
c = remaining distance in cycle
```

When `slow` and `fast` meet:

```text
slow distance = a + b
fast distance = a + b + c + b
```

Since `fast` moves twice as fast:

```text
2(a + b) = a + 2b + c
```

Therefore:

```text
a = c
```

This means the distance from the **head to the cycle entry** is equal to the distance from the **meeting point around the cycle to the cycle entry**.

So, if we start:

```text
entry → head
slow  → meeting point
```

and move both one step at a time, they will meet exactly at the **cycle entry**.

### Important Difference: 141 vs 142

**141. Linked List Cycle**

Question:

> Does a cycle exist?

Return:

```javascript
true / false
```

**142. Linked List Cycle II**

Question:

> Where does the cycle begin?

Return:

```javascript
entry node / null
```

---

### Important Code Logic

Cycle detection:

```javascript
if (slow == fast) {
```

Then reset one pointer:

```javascript
let entry = head;
```

Move both equally:

```javascript
while (entry !== slow) {
    entry = entry.next;
    slow = slow.next;
}
```

Return the meeting point:

```javascript
return entry;
```

---

### Complexity

**Time:** `O(n)`

**Space:** `O(1)`

---

### Common Mistakes

❌ Moving `entry` two steps:

```javascript
entry = entry.next.next;
```

✅ Move both one step:

```javascript
entry = entry.next;
slow = slow.next;
```

---

❌ Returning `true` when the pointers meet.

This problem asks for the **cycle's starting node**, not just whether a cycle exists.

✅ Return:

```javascript
return entry;
```

### Key Interview Point

> **141 → Detect whether a cycle exists.**
>
> **142 → Detect the cycle first, then find its starting node using Floyd's algorithm.**

### Pattern to Remember

```text
Linked List
     ↓
Fast & Slow Pointer
     ↓
Do they meet?
   ↙       ↘
 No        Yes
 ↓          ↓
null    Reset one pointer
             ↓
       Move both by 1
             ↓
       Cycle Entry
```
