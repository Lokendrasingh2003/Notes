# 1922. Count Good Numbers

## 📌 Problem

A digit string is **good** if:

* Digits at **even indices** are even: `0, 2, 4, 6, 8` → **5 choices**
* Digits at **odd indices** are prime: `2, 3, 5, 7` → **4 choices**

Find the total number of good strings of length `n`.

Return the answer modulo:

```text
10^9 + 7
```

---

## 🧠 Pattern

**Math + Combinatorics + Binary Exponentiation**

---

## 💡 Key Idea

The positions are independent.

For a string of length `n`:

### Even positions

Indices:

```text
0, 2, 4, 6, ...
```

There are:

```text
ceil(n / 2)
```

even positions.

Each has **5 choices**:

```text
0, 2, 4, 6, 8
```

So:

```text
5^(ceil(n/2))
```

### Odd positions

Indices:

```text
1, 3, 5, 7, ...
```

There are:

```text
floor(n / 2)
```

odd positions.

Each has **4 choices**:

```text
2, 3, 5, 7
```

So:

```text
4^(floor(n/2))
```

Therefore:

```text
Answer = 5^(ceil(n/2)) × 4^(floor(n/2))
```

---

# 🔢 Why Multiplication?

Suppose:

```text
n = 4
```

Positions:

```text
Index:    0   1   2   3
          E   O   E   O
Choices:  5   4   5   4
```

Total:

```text
5 × 4 × 5 × 4
= 5² × 4²
= 25 × 16
= 400
```

So the answer is:

```text
400
```

---

# 🚀 Why Binary Exponentiation?

The constraint is:

```text
n <= 10^15
```

We cannot calculate:

```js
5^500000000000000
```

using a loop.

A normal loop would take:

```text
O(n)
```

which is impossible for such a large `n`.

Instead, we use **Binary Exponentiation**.

It calculates:

```text
x^n
```

in:

```text
O(log n)
```

---

# 🔍 Your Code

```js
var countGoodNumbers = function(n) {

    const MOD = 1000000007n;

    let evenPositions = BigInt(Math.ceil(n / 2));
    let oddPositions = BigInt(Math.floor(n / 2));

    let evenWays = power(5n, evenPositions, MOD);
    let oddWays = power(4n, oddPositions, MOD);

    return Number((evenWays * oddWays) % MOD);
};
```

The important part is:

```js
let evenPositions = BigInt(Math.ceil(n / 2));
let oddPositions = BigInt(Math.floor(n / 2));
```

Then:

```js
5^(evenPositions)
```

and:

```js
4^(oddPositions)
```

Finally:

```js
(evenWays * oddWays) % MOD
```

# ⚡ Binary Exponentiation

Your function:

```js
function power(x, n, MOD) {

    if(n === 0n){
        return 1n;
    }

    let half = power(x, n / 2n, MOD);

    if(n % 2n === 0n){
        return (half * half) % MOD;
    }

    return (x * half * half) % MOD;
}
```

The main idea is:

```text
x^n
```

Instead of multiplying `x` `n` times, divide the exponent by `2`.

### If `n` is even

```text
x^n = x^(n/2) × x^(n/2)
```

Therefore:

```js
half * half
```

### If `n` is odd

```text
x^n = x × x^(n/2) × x^(n/2)
```

Therefore:

```js
x * half * half
```

# 🔎 Binary Exponentiation Dry Run

For:

```text
power(5, 4)
```

Instead of:

```text
5 × 5 × 5 × 5
```

we do:

```text
5^4
→ 5^2 × 5^2
→ (5^1 × 5^1) × (5^1 × 5^1)
→ 25 × 25
→ 625
```

The recursion only goes through:

```text
4 → 2 → 1 → 0
```

rather than performing 4 separate multiplications.

For very large values such as `10^15`, this becomes:

```text
10^15 → 5×10^14 → ... 
```

with only about **50 recursive levels**.

# 🧠 Why BigInt Is Necessary

JavaScript's normal `Number` cannot safely represent every integer beyond:

```text
2^53 - 1
```

But our exponent can be as large as:

```text
10^15
```

and intermediate multiplication can also become very large.

That's why your code uses:

```js
1000000007n
5n
4n
```

The `n` means these are **BigInt** values.

For example:

```js
5n * 5n
```

is BigInt arithmetic.

You cannot mix `Number` and `BigInt` directly:

```js
5n * 5 // Error
```

Your code correctly keeps the power calculation in BigInt and only converts the final result:

```js
return Number((evenWays * oddWays) % MOD);
```

# ⚠️ Important JavaScript Detail

This is also why you have:

```js
if(n === 0n)
```

instead of:

```js
if(n === 0)
```

Because your `n` inside `power()` is a BigInt.

Similarly:

```js
n / 2n
```

and:

```js
n % 2n
```

must use BigInt operands.

# ⏱️ Complexity

Let `n` be the given length.

### Time

Binary exponentiation takes:

```text
O(log n)
```

We calculate two powers:

```text
5^(ceil(n/2))
4^(floor(n/2))
```

Therefore:

```text
O(log n) + O(log n)
= O(log n)
```

### Space

Because your implementation is recursive:

```text
O(log n)
```

for the recursion stack.

So your exact solution has:

```text
Time:  O(log n)
Space: O(log n)
```

If binary exponentiation were implemented iteratively, auxiliary space could be reduced to:

```text
O(1)
```

# ⚠️ Common Mistakes

### 1. Treating every position as having 5 choices

Wrong:

```text
5^n
```

Odd positions only have 4 choices.

Correct:

```text
5^(even positions) × 4^(odd positions)
```

---

### 2. Confusing even digits with even positions

The condition is based on the **index**, not the digit.

For:

```text
"2582"
```

indices are:

```text
0 1 2 3
2 5 8 2
```

Positions `0` and `2` need even digits.

Positions `1` and `3` need prime digits.

---

### 3. Using a normal loop for exponentiation

Something like:

```js
for(let i = 0; i < n; i++)
```

will not work for:

```text
n = 10^15
```

Use binary exponentiation.

---

### 4. Forgetting modulo during multiplication

Do:

```js
(half * half) % MOD
```

rather than waiting until the very end.

---

### 5. Mixing Number and BigInt

Wrong:

```js
5n * 4
```

Correct:

```js
5n * 4n
```

# 🎯 Interview Explanation

If the interviewer asks **"Explain your approach"**, you can say:

> "There are 5 choices for every even index and 4 choices for every odd index. For a string of length n, there are ceil(n/2) even positions and floor(n/2) odd positions. So the answer is 5^(ceil(n/2)) × 4^(floor(n/2)). Since n can be as large as 10^15, I calculate both powers using binary exponentiation in O(log n) time. I use BigInt because JavaScript Number cannot safely handle the required integer calculations."
