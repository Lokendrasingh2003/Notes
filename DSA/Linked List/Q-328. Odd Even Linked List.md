# 328. Odd Even Linked List

# Link : https://leetcode.com/problems/odd-even-linked-list/

### Pattern

**Linked List + Pointer Manipulation**

### Problem

Given a singly linked list, group all nodes at **odd indices** together, followed by all nodes at **even indices**.

The first node has index `1` (odd).

The relative order of nodes inside both groups must remain unchanged.

Example:

```text
Input:
1 → 2 → 3 → 4 → 5

Output:
1 → 3 → 5 → 2 → 4
```

---

## Important Clarification

"Odd" and "Even" refer to the **position/index of the node**, not its value.

For:

```text
10 → 15 → 20 → 25 → 30
```

Positions are:

```text
10 → 15 → 20 → 25 → 30
 ↑     ↑     ↑     ↑     ↑
 1     2     3     4     5
 O     E     O     E     O
```

So the result is:

```text
10 → 20 → 30 → 15 → 25
```

---

# Approach

Maintain three pointers:

```javascript
let odd = head;
let even = head.next;
let evenHead = head.next;
```

### `odd`

Points to the current odd-indexed node.

### `even`

Points to the current even-indexed node.

### `evenHead`

Stores the **first even node** because we need to attach the even list after the odd list at the end.

---

## Step 1: Separate Odd and Even Nodes

For:

```text
1 → 2 → 3 → 4 → 5
```

Initially:

```text
odd  = 1
even = 2
```

We change:

```javascript
odd.next = odd.next.next;
```

So:

```text
1 → 3 → 4 → 5
```

Then move:

```javascript
odd = odd.next;
```

Now:

```text
odd = 3
```

---

## Step 2: Build the Even List

Similarly:

```javascript
even.next = even.next.next;
```

This connects:

```text
2 → 4
```

Then:

```javascript
even = even.next;
```

Now `even` points to `4`.

---

## Step 3: Continue Until the Lists Are Separated

Eventually we have:

```text
Odd list:

1 → 3 → 5


Even list:

2 → 4
```

Then connect them:

```javascript
odd.next = evenHead;
```

Result:

```text
1 → 3 → 5 → 2 → 4
```

---

# Code

```javascript
var oddEvenList = function(head) {
    if (head == null || head.next == null) {
        return head;
    }

    let odd = head;
    let even = head.next;
    let evenHead = head.next;

    while (odd.next != null && odd != null && 
           even.next != null && even != null) {

        odd.next = odd.next.next;
        odd = odd.next;

        even.next = even.next.next;
        even = even.next;
    }

    // Connect odd list with even list
    odd.next = evenHead;

    return head;
};
```

---

# Cleaner Version

Your solution works, but the condition in your `while` loop is more complicated than necessary.

You can write it more cleanly as:

```javascript
var oddEvenList = function(head) {
    if (head == null || head.next == null) {
        return head;
    }

    let odd = head;
    let even = head.next;
    let evenHead = even;

    while (even != null && even.next != null) {
        odd.next = even.next;
        odd = odd.next;

        even.next = odd.next;
        even = even.next;
    }

    odd.next = evenHead;

    return head;
};
```

### Why is this cleaner?

You only need to check:

```javascript
even != null && even.next != null
```

because `even` is always ahead of `odd`.

You don't need:

```javascript
odd.next != null && odd != null
```

separately.

# Dry Run

Input:

```text
1 → 2 → 3 → 4 → 5
```

Initially:

```text
odd       even
 ↓         ↓
 1 → 2 → 3 → 4 → 5
     ↑
  evenHead
```

After first iteration:

```text
1 → 3 → 5
```

and:

```text
2 → 4
```

After processing:

```text
odd = 5
even = null
```

Finally:

```javascript
odd.next = evenHead;
```

So:

```text
1 → 3 → 5 → 2 → 4
```

---

# Why Do We Store `evenHead`?

This is one of the most important things to remember.

Initially:

```javascript
let evenHead = head.next;
```

For:

```text
1 → 2 → 3 → 4 → 5
```

`evenHead` points to:

```text
2
```

Later, `even` moves:

```text
2 → 4 → null
```

So if we didn't save the original `2`, we wouldn't know where the even list starts.

That's why:

```javascript
let evenHead = even;
```

is important.

# Complexity

### Time: `O(n)`

We traverse the linked list once.

```text
O(n)
```

### Space: `O(1)`

We only use a few pointers:

```text
odd
even
evenHead
```

No extra array or linked list is created.

```text
O(1)
```

# Important Interview Point

The problem does **not** ask you to create a new list.

You are rearranging the existing nodes by changing their `next` pointers.

Think:

```text
Original List
      ↓
Separate Odd + Even Chains
      ↓
Connect Odd → Even
```

# Pattern to Remember

When you see:

> "Group odd/even indexed nodes while maintaining order"

Think:

```text
odd  → odd  → odd
              ↓
            evenHead
              ↓
even → even → even
```

### One-Line Memory Trick

> **Maintain odd pointer + even pointer + save evenHead → rearrange links → connect odd to evenHead.**

# Common Mistakes

### ❌ Mistake 1: Using node values

Don't check:

```javascript
node.val % 2
```

The problem is based on **index**, not value.

---

### ❌ Mistake 2: Forgetting `evenHead`

If you don't save:

```javascript
let evenHead = even;
```

you lose the starting point of the even list.

---

### ❌ Mistake 3: Creating a new array

Something like:

```javascript
let arr = [];
```

would violate the spirit of the `O(1)` extra-space requirement.

---

### ❌ Mistake 4: Forgetting to connect the lists

At the end:

```javascript
odd.next = evenHead;
```

is essential.

Without it, you have two separate lists instead of one.
