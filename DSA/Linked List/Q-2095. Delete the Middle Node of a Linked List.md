# 2095. Delete the Middle Node of a Linked List

# Link : https://leetcode.com/problems/delete-the-middle-node-of-a-linked-list/

### Pattern

**Fast & Slow Pointer + Node Deletion**

### Problem

Given the head of a singly linked list, delete the **middle node** and return the modified list.

The middle is based on **0-based indexing**:

```text
n = 1 → index 0
n = 2 → index 1
n = 3 → index 1
n = 4 → index 2
n = 5 → index 2
```

Example:

```text
1 → 3 → 4 → 7 → 1 → 2 → 6
```

There are `7` nodes, so the middle node is:

```text
7
```

After deletion:

```text
1 → 3 → 4 → 1 → 2 → 6
```

---

## Key Idea

Use **slow and fast pointers**.

But there is an important difference from the normal "find middle" problem.

We don't want `slow` to point **at** the middle.

We want `slow` to point to the **node before the middle**.

Why?

Because to delete a node in a singly linked list, we need access to the previous node:

```text
previous → middle → next
```

Then we can skip the middle:

```text
previous → next
```

Using:

```javascript
slow.next = slow.next.next;
```

---

# Approach

### Step 1: Handle small lists

If there are 1 or 0 nodes:

```javascript
if (head == null || head.next == null) {
    return null;
}
```

For:

```text
1
```

the only node is the middle, so deleting it gives:

```text
null
```

---

### Step 2: Initialize pointers

Your solution uses:

```javascript
let slow = head;
let fast = head.next.next;
```

The important part is:

```javascript
fast = head.next.next;
```

This starting position makes `slow` stop at the **node before the middle**.

---

### Step 3: Move pointers

```javascript
while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
}
```

`slow` moves one step while `fast` moves two steps.

When the loop ends:

```text
slow → node before middle
```

---

### Step 4: Delete the middle

Now:

```javascript
slow.next = slow.next.next;
```

Suppose we have:

```text
1 → 2 → 3 → 4
    ↑
   slow
```

Here `3` is the middle.

So:

```javascript
slow.next = slow.next.next;
```

changes:

```text
2 → 3 → 4
```

into:

```text
2 → 4
```

Final list:

```text
1 → 2 → 4
```

---

# Code

```javascript
var deleteMiddle = function(head) {

    // If there is only one node,
    // deleting the middle leaves an empty list.
    if (head == null || head.next == null) {
        return null;
    }

    let slow = head;
    let fast = head.next.next;

    // Find the node before the middle
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
    }

    // Delete the middle node
    slow.next = slow.next.next;

    return head;
};
```

# Dry Run

Consider:

```text
1 → 3 → 4 → 7 → 1 → 2 → 6
```

There are `7` nodes.

The middle is:

```text
7
```

We want `slow` to stop at:

```text
4
```

So that:

```text
slow.next = 7
```

Then:

```javascript
slow.next = slow.next.next;
```

becomes:

```text
4.next = 1
```

Result:

```text
1 → 3 → 4 → 1 → 2 → 6
```

# Why `fast = head.next.next`?

This is the most important detail in your solution.

Normally, for finding the middle, we might start:

```javascript
slow = head;
fast = head;
```

But here we need `slow` to stop **one node before the middle**.

Therefore:

```javascript
fast = head.next.next;
```

shifts the position so that `slow` ends up at the predecessor of the middle.

### Example: 4 nodes

```text
1 → 2 → 3 → 4
```

Initial:

```text
slow = 1
fast = 3
```

The loop condition:

```javascript
fast != null && fast.next != null
```

is true because:

```text
fast = 3
fast.next = 4
```

Move:

```text
slow = 2
fast = null
```

Loop stops.

So:

```text
slow = 2
slow.next = 3
```

And `3` is exactly the middle node.

Delete it:

```text
1 → 2 → 4
```

# Another Way to Think About It

The whole problem is basically:

```text
Find previous node
       ↓
     Middle
       ↓
     Next
```

Then bypass the middle:

```text
Previous ─────────→ Next
```

The deletion itself is only:

```javascript
slow.next = slow.next.next;
```

The main challenge is correctly positioning `slow`.

# Important Interview Point

For **finding the middle**:

```text
slow → middle
```

For **deleting the middle**:

```text
slow → node BEFORE middle
```

This distinction is very important.

### Remember:

> **To delete a node in a singly linked list, position your pointer at the node before it.**

Then:

```javascript
previous.next = previous.next.next;
```

# Pattern to Remember

```text
Fast & Slow Pointer
        ↓
Position slow BEFORE middle
        ↓
Skip middle
        ↓
slow.next = slow.next.next
```

# Common Mistakes

### ❌ Mistake 1: Starting fast at head

```javascript
let fast = head;
```

This can make `slow` point to the middle itself rather than the node before it.

For this particular implementation, use:

```javascript
let fast = head.next.next;
```

---

### ❌ Mistake 2: Doing this

```javascript
slow = slow.next;
```

after finding the middle.

You don't want to move `slow` onto the middle because then you lose access to its previous node.

---

### ❌ Mistake 3: Forgetting the single-node case

For:

```text
1
```

the answer must be:

```text
null
```

So:

```javascript
if (head == null || head.next == null) {
    return null;
}
```

is necessary.
