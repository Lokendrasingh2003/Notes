# 234. Palindrome Linked List

# Link : https://leetcode.com/problems/palindrome-linked-list/description/

### Pattern

**Fast & Slow Pointer + Reverse Second Half + Two Pointer**

### Problem

Given the head of a singly linked list, return `true` if the linked list is a palindrome.

A palindrome reads the same forward and backward.

Example:

```text
1 → 2 → 2 → 1
```

Output:

```text
true
```

But:

```text
1 → 2
```

Output:

```text
false
```

---

## Optimal Approach

We can solve this in **O(n) time and O(1) space** using 3 steps:

### Step 1: Find the Middle

Use two pointers:

* `slow` → moves 1 step
* `fast` → moves 2 steps

When `fast` reaches the end, `slow` will be around the middle.

```javascript
let slow = head;
let fast = head;

while (fast.next != null && fast.next.next != null) {
    slow = slow.next;
    fast = fast.next.next;
}
```

For:

```text
1 → 2 → 2 → 1
```

`slow` will point to the first `2`.

---

### Step 2: Reverse the Second Half

Reverse the list starting from:

```javascript
slow.next
```

```javascript
let newHead = reverse(slow.next);
```

The list becomes conceptually:

```text
First half:
1 → 2

Second half:
1 → 2
```

---

### Step 3: Compare Both Halves

Use two pointers:

```javascript
let first = head;
let second = newHead;
```

Compare their values:

```javascript
while (second != null) {
    if (first.val != second.val) {
        return false;
    }

    first = first.next;
    second = second.next;
}
```

If every value matches, the linked list is a palindrome.

---

## Code

```javascript
var isPalindrome = function(head) {
    if (head == null || head.next == null) {
        return true;
    }

    // Step 1: Find middle
    let slow = head;
    let fast = head;

    while (fast.next != null && fast.next.next != null) {
        slow = slow.next;
        fast = fast.next.next;
    }

    // Step 2: Reverse second half
    let newHead = reverse(slow.next);

    let first = head;
    let second = newHead;

    // Step 3: Compare both halves
    while (second != null) {
        if (first.val != second.val) {
            reverse(newHead);
            return false;
        }

        first = first.next;
        second = second.next;
    }

    // Restore original linked list
    reverse(newHead);

    return true;

    function reverse(head) {
        if (head == null || head.next == null) {
            return head;
        }

        let newHead = reverse(head.next);

        let temp = head.next;
        temp.next = head;
        head.next = null;

        return newHead;
    }
};
```

## Dry Run

Consider:

```text
1 → 2 → 2 → 1
```

### Step 1: Find Middle

Initially:

```text
slow = 1
fast = 1
```

After moving:

```text
slow = 2
fast = 2
```

So:

```text
1 → 2 → 2 → 1
    ↑
   slow
```

---

### Step 2: Reverse Second Half

We reverse:

```text
2 → 1
```

into:

```text
1 → 2
```

Now we compare:

```text
first:   1 → 2 → ...
second:  1 → 2
```

---

### Step 3: Compare

```text
1 == 1 ✅
2 == 2 ✅
```

Everything matches.

Therefore:

```javascript
return true;
```

---

## Why `fast.next && fast.next.next`?

You use:

```javascript
while (fast.next != null && fast.next.next != null)
```

because inside the loop you move:

```javascript
fast = fast.next.next;
```

We need to make sure both nodes exist before accessing them.

This also positions `slow` correctly so that:

```javascript
slow.next
```

represents the beginning of the second half.

---

## Why Compare Only Until `second != null`?

```javascript
while (second != null)
```

The second half will never be longer than the first half.

So once `second` reaches `null`, we have compared all the nodes that need to be checked.

---

## Why Reverse the List Again?

You have:

```javascript
reverse(newHead);
```

at the end.

This restores the linked list to its original structure.

It's not strictly necessary for determining the answer, but it's a good practice because the function doesn't unnecessarily modify the input list.

You also restore it before returning `false`:

```javascript
if (first.val != second.val) {
    reverse(newHead);
    return false;
}
```

## Complexity

### Time: `O(n)`

We:

* Find the middle → `O(n)`
* Reverse the second half → `O(n)`
* Compare → `O(n)`
* Restore → `O(n)`

Overall:

```text
O(n)
```

### Space: `O(1)`

We only use a few pointers:

```text
slow
fast
first
second
newHead
```

So auxiliary space is:

```text
O(1)
```

**Note:** Your `reverse()` is implemented recursively, so in JavaScript it uses `O(n)` call-stack space in the worst case. If the interviewer strictly asks for **O(1) auxiliary space**, use an **iterative reverse** instead.

---

## Important Interview Pattern

When you see:

> "Check whether a linked list is a palindrome"

Think:

```text
Find Middle
     ↓
Reverse Second Half
     ↓
Compare First & Second Half
     ↓
Restore List
```

### One-Line Memory Trick

> **Middle → Reverse → Compare → Restore**
