# 90. Subsets II

## 📌 Problem

Given an array `nums` that **may contain duplicates**, return all possible subsets without duplicate subsets.

Example:

```text
nums = [1, 2, 2]

Output:
[
  [],
  [1],
  [1,2],
  [1,2,2],
  [2],
  [2,2]
]
```

The important part is:

> **The input can contain duplicates, but the result must not contain duplicate subsets.**

---

## 🧠 Pattern

**Backtracking + Sorting + Same-Level Duplicate Skipping**

The main idea is:

```text
Sort → Backtrack → Skip duplicates at same level → Pick → Recurse → Pop
```

---

## 💡 Key Idea

First sort the array:

```js
nums.sort((a, b) => a - b)
```

For:

```text
[1, 2, 2]
```

it is already:

```text
[1, 2, 2]
```

Sorting puts duplicate values next to each other.

Then, inside the loop:

```js
if (i > index && nums[i] == nums[i - 1]) {
    continue
}
```

we skip a duplicate **only when it appears at the same recursion level**.

This is the most important line of the problem.

---

## 🔍 Your Code

```js
var subsetsWithDup = function(nums) {

    nums.sort((a,b)=>a-b)

    let result = []

    function backtracking(index,current){

        result.push([...current])

        for(let i=index;i<nums.length;i++){

            if(i>index && nums[i]==nums[i-1]){
                continue
            }

            current.push(nums[i])
            backtracking(i+1,current)
            current.pop()
        }        
    }

    backtracking(0,[])

    return result
};
```

Your implementation is correct. ✅

---

# 🔄 How the Recursion Works

Unlike **Subsets I**, here we use a loop.

At every recursion level:

```js
for(let i=index; i<nums.length; i++)
```

we try each possible element as the next element of the subset.

For every choice:

```text
Pick → Recurse → Undo
```

which is implemented as:

```js
current.push(nums[i])

backtracking(i + 1, current)

current.pop()
```

---

## ⭐ Why `result.push([...current])` Comes First

This line:

```js
result.push([...current])
```

is executed **before the loop**.

Why?

Because every state of `current` represents a valid subset.

For example:

```text
[]
[1]
[1,2]
[1,2,2]
[2]
[2,2]
```

So we store the current subset at every recursion level.

The spread operator:

```js
[...current]
```

is important because it creates a **copy**.

If we wrote:

```js
result.push(current)
```

all entries would reference the same array and later modifications would affect them.

---

# 🚨 Most Important Part: Duplicate Handling

Consider:

```text
nums = [1,2,2]
```

At the first recursion level:

```text
i = 0 → choose 1
i = 1 → choose 2
i = 2 → choose 2
```

If we choose both `nums[1]` and `nums[2]` as the **first element**, they would both create:

```text
[2]
```

That would be a duplicate.

So:

```js
if(i > index && nums[i] == nums[i-1]){
    continue
}
```

skips the second `2` at that level.

---

# ❗ Why `i > index` Is Important

This is a very common interview question.

Suppose:

```text
nums = [1,2,2]
```

We want:

```text
[2]
[2,2]
```

So we **cannot simply skip every duplicate**.

The second `2` must still be allowed at a **deeper recursion level**.

### Same level

```text
[2]     ← choose first 2
[2]     ← choose second 2
```

These are duplicates, so skip the second choice.

### Deeper level

```text
[2]
  |
  └── [2,2]
```

This is a different subset, so it must be allowed.

That's why:

```js
i > index
```

means:

> "Skip this duplicate only if another identical value has already been considered at this same recursion level."

# 🧪 Dry Run

For:

```text
nums = [1,2,2]
```

### Start

```text
current = []
```

Store:

```text
[]
```

Loop:

```text
i = 0 → choose 1
```

```text
current = [1]
```

Store:

```text
[1]
```

Then:

```text
i = 1 → choose 2
```

```text
current = [1,2]
```

Store:

```text
[1,2]
```

Then `i = 2` is allowed because we are at a **deeper level**:

```text
current = [1,2,2]
```

Store:

```text
[1,2,2]
```

Backtrack:

```text
[1,2] → [1] → []
```

Now at the root level:

```text
i = 1 → choose 2
```

```text
current = [2]
```

Store:

```text
[2]
```

Then choose the second `2`:

```text
current = [2,2]
```

Store:

```text
[2,2]
```

Finally:

```text
i = 2
```

at the root level:

```js
i > index
nums[2] === nums[1]
```

so:

```js
continue
```

Therefore, another `[2]` is not generated.

Final result:

```text
[
  [],
  [1],
  [1,2],
  [1,2,2],
  [2],
  [2,2]
]
```

# 🔥 Subsets I vs Subsets II

|                    | Subsets I             | Subsets II             |
| ------------------ | --------------------- | ---------------------- |
| Duplicate input    | Usually no duplicates | Can contain duplicates |
| Sorting            | Not required          | Required               |
| Duplicate handling | Not needed            | Same-level skip        |
| Backtracking       | Yes                   | Yes                    |
| Store subset       | Every recursion state | Every recursion state  |
| Main trick         | Pick / Skip           | Sort + Skip duplicates |

### Subsets I

```text
Pick / Not Pick
```

### Subsets II

```text
Sort
↓
Loop
↓
Skip duplicate at same level
↓
Pick
↓
Recurse
↓
Pop
```

---

## ⚡ Important Line

```js
if(i > index && nums[i] == nums[i-1]){
    continue
}
```

### Remember:

> **Same level → skip duplicate.**
> **Different level → allow duplicate.**

This is the key concept you should remember for interviews.

---

# 🔗 Why `backtracking(i + 1, current)`?

Once we choose:

```js
nums[i]
```

we move to:

```js
i + 1
```

because each array element can be used **at most once** in a subset.

Example:

```text
[1,2,2]

choose nums[1] = 2

next search starts from index 2
```

So we can still choose the second `2`:

```text
[2,2]
```

but we cannot choose the same array position again.

---

# ⏱️ Complexity

There can be up to:

```text
2^n
```

subsets.

Sorting takes:

```text
O(n log n)
```

Backtracking takes approximately:

```text
O(2^n)
```

Additionally, copying each subset costs up to `O(n)`.

A common interview complexity description is:

```text
Time: O(n log n + n × 2^n)
Auxiliary Space: O(n)
```

where `O(n)` is the recursion/current-path space, excluding the output.

The result itself can contain up to `2^n` subsets, so output space is exponential.

---

# 🗣️ Interview Explanation

> "I first sort the array so duplicate values are adjacent. Then I use backtracking to generate every subset. At each recursion level, I loop from the current index and choose an element. Before choosing it, I check whether it is the same as the previous element and whether I'm still at the same recursion level. If `i > index` and the values are equal, I skip it to avoid generating the same subset again. After choosing an element, I recurse with `i + 1`, and then remove it using `pop` to backtrack."

---

# 🧠 Memory Trick

### **Sort → Skip Same Level → Pick → Recurse → Pop**

And remember this one line:

```text
i > index + same value = skip
```

Or simply:

> **Same level = Skip, New level = Allow.**

That is the main trick behind **Subsets II**.
